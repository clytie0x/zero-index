20.4 unordered_map และ unordered_set

set กับ map เรียงข้อมูลให้ตลอดเวลา จึงตอบได้ว่าค่าน้อยสุดคืออะไร หรือค่าแรกที่ ≥ x คืออะไร แต่ถ้าโจทย์ถามแค่ว่ามีไหม หรือนับว่ากี่ครั้ง การเรียงไว้ก็เป็นงานที่เปล่าประโยชน์ C++ มีอีกคู่หนึ่งที่ไม่เรียง คือ unordered_set กับ unordered_map ใช้คำสั่งชุดเดียวกัน แต่ข้างในเป็นตารางแฮช (hash table) ซึ่งแต่ละคำสั่งใช้เวลาเฉลี่ย O(1) หน้านี้ดูว่าเร็วขึ้นจริงแค่ไหน และกรณีไหนที่มันช้าลงจนแพ้ map แบบไม่เห็นฝุ่น

ตารางแฮชทำงานยังไง

นึกถึงอาเรย์นับในหน้า 5.3 ที่ใช้ค่าเป็นหมายเลขช่องตรงๆ เร็วมากแต่ต้องมีช่องเท่ากับช่วงของค่า ตารางแฮชแก้ด้วยการมีช่องจำนวนพอประมาณ เรียกว่า bucket แล้วแปลงค่าเป็นหมายเลขช่องด้วยการ mod กับจำนวนช่อง ถ้ามี 7 ช่อง ค่า 40 ไปอยู่ช่อง 40 % 7 = 5 ค่าที่ตกช่องเดียวกันต่อกันเป็นรายการในช่องนั้น เหมือน linked list ในบทที่ 14

หาค่า 22 ก็คำนวณ 22 % 7 = 1 แล้วไล่ดูเฉพาะช่อง 1 ซึ่งมีแค่สองตัว ไม่ต้องดูช่องอื่นเลย ตารางแฮชของ C++ คอยเพิ่มจำนวนช่องให้มากกว่าจำนวนค่าเสมอ พอค่าเพิ่มจนแน่นก็ขยายตารางแล้วย้ายทุกค่าไปช่องใหม่ ถ้าค่ากระจายตัวดี แต่ละช่องมีของแค่หนึ่งสองตัว ทุกคำสั่งจึงใช้เวลาเฉลี่ย O(1) ค่าที่ไม่ใช่ตัวเลขเช่นข้อความ จะถูกแปลงเป็นตัวเลขด้วยฟังก์ชันแฮชก่อน แล้วค่อย mod

ใช้งานเหมือน set และ map

เปลี่ยนชื่อชนิดอย่างเดียว คำสั่ง insert count find erase size และวงเล็บเหลี่ยมของ map ใช้ได้เหมือนเดิมทุกอย่าง รวมถึงกับดักวงเล็บเหลี่ยมสร้างคีย์ในหน้า 20.3 ด้วย สิ่งที่หายไปคือทุกอย่างที่อาศัยลำดับ

  • ไม่มี lower_bound upper_bound
  • begin() ไม่ใช่ค่าน้อยสุด และไม่มี rbegin()
  • วนด้วย for แล้วได้ลำดับที่เดาไม่ได้ ไม่ใช่จากน้อยไปมาก และไม่ใช่ตามลำดับที่ใส่

ตัวอย่างการใช้งานจริงอยู่ในหัวข้อจับคู่ผลรวมข้างล่าง

เร็วกว่า map แค่ไหน

นับความถี่ของตัวเลขสุ่ม 0 ถึง 109 ด้วย map<int, int> เทียบกับ unordered_map<int, int> โค้ดเหมือนโปรแกรม calls ในหน้า 20.3 ต่างกันแค่ชื่อชนิด จับเวลาเฉพาะช่วงนับ

map<int, int> tree_count;
for (int x : values) {
    tree_count[x]++;
}
unordered_map<int, int> hash_count;
for (int x : values) {
    hash_count[x]++;
}

เลือกตัวไหนเป็นค่าเริ่มต้น

ใช้ map กับ set เป็นค่าเริ่มต้น เพราะเวลาแน่นอนทุกกรณีและใช้ lower_bound ได้ เปลี่ยนเป็นแบบ unordered เมื่อไม่ต้องการลำดับ และวัดแล้วว่าเวลาเฉียดขอบ

ตัวอย่าง จับคู่ผลรวมเท่ากับ K

น้องได้บัตรของขวัญมูลค่า K บาท ร้านมีสินค้า N ชิ้นเรียงบนชั้น อยากซื้อของสองชิ้นที่ราคารวมเท่ากับ K พอดี ให้บอกตำแหน่งของสองชิ้นนั้น ถ้ามีหลายคู่ ตอบคู่ไหนก็ได้ ถ้าไม่มีให้พิมพ์ no pair

ไล่ชิ้นที่ j จากซ้ายไปขวา ชิ้นที่ j ราคา p ต้องการคู่ราคา K - p ถ้าราคานั้นเคยเจอในชิ้นก่อนหน้าก็จบ จึงต้องจดไว้ว่าราคาที่เคยเจออยู่ตำแหน่งไหน งานแบบนี้คือ map ที่ไม่ต้องเรียง

#include <bits/stdc++.h>
using namespace std;

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    long long target;
    cin >> n >> target;
    unordered_map<long long, int> position;
    for (int j = 1; j <= n; j++) {
        long long price;
        cin >> price;
        auto it = position.find(target - price); // (1)!
        if (it != position.end()) {
            cout << it->second << ' ' << j << '\n';
            return 0;
        }
        position[price] = j; // (2)!
    }
    cout << "no pair\n";
    return 0;
}
  1. ใช้ find ไม่ใช่วงเล็บเหลี่ยม เพราะแค่ถาม ไม่อยากสร้างคีย์ราคาที่ไม่มีอยู่จริงทิ้งไว้
  2. จดราคานี้หลังจากถามแล้ว ถ้าจดก่อน ของราคา K/2 ชิ้นเดียวจะจับคู่กับตัวเอง ถ้าราคาซ้ำ ตำแหน่งจะถูกเขียนทับด้วยชิ้นหลัง ซึ่งไม่ผิดเพราะโจทย์ขอคู่ไหนก็ได้

เทียบสี่วิธีกับราคาสุ่ม 1 ถึง 109 N ชิ้น K = 109 และนับทุกคู่ให้ครบแทนการหยุดที่คู่แรก ทุกวิธีจะได้ทำงานเต็มที่

  • สองลูป ลองทุกคู่ i < j ตรงๆ O(N2)
  • sort แล้วค้นหา เรียงราคา แล้วแต่ละชิ้นใช้ lower_bound กับ upper_bound ในหน้า 19.2 นับว่าราคา K - p มีกี่ชิ้นถัดไปทางขวา O(N log N)
  • map แบบโปรแกรม gift แต่เก็บจำนวนชิ้นของแต่ละราคา O(N log N)
  • unordered_map เหมือนข้อก่อน เฉลี่ย O(N)

สรุป

  • unordered_set กับ unordered_map ใช้คำสั่งเหมือน set กับ map แต่ไม่เรียง ไม่มี lower_bound และวนได้ลำดับที่เดาไม่ได้
  • ข้างในเป็นตารางแฮช แต่ละคำสั่งเฉลี่ย O(1) แต่ถ้าค่าชนช่องเดียวกันมากๆ จะเป็น O(N)
  • วัดจริงเร็วกว่า map ไม่กี่เท่า แต่กรณีแย่สุดช้ากว่าหลายร้อยเท่า ใช้ map เป็นค่าเริ่มต้น
  • จับคู่ผลรวมเท่ากับ K ไล่ไปทีละตัวแล้วถามว่าเคยเห็น K - x ไหม ถามก่อนแล้วค่อยจด
  • ข้อมูลมาครบตั้งแต่ต้น sort แล้วค้นหาก็เร็วพอๆ กัน
